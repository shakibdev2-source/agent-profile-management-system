## 🛡️ Security Architecture

<div align="center">

```
 ┌────────────────────────────────────────────────────────────────────┐
 │                    ENCRYPTION PIPELINE                              │
 ├────────────────────────────────────────────────────────────────────┤
 │                                                                    │
 │  [Password]  ──→  PBKDF2-SHA256(600K)  ──→  256-bit Base Key      │
 │                                                  │                 │
 │  [KeyFile]   ──→  SHA-256(file bytes)  ──XOR──→  Final Key        │
 │                                                  │                 │
 │  [Plaintext] ──→  zlib.compress(L6)   ──→  Compressed Data       │
 │                                                  │                 │
 │                   AES-256-CBC  ←──  random IV (128-bit)           │
 │                        │                                           │
 │                   Ciphertext                                       │
 │                        │                                           │
 │                   HMAC-SHA256(CT)  ──→  32-byte MAC               │
 │                                                                    │
 ├────────────────────────────────────────────────────────────────────┤
 │                    .locked FILE FORMAT                              │
 ├────────────────────────────────────────────────────────────────────┤
 │  MAGIC(7) │ SALT_R(32) │ IV_R(16) │ HMAC_R(32) │ CT_REAL(N)      │
 │  SALT_D(32) │ IV_D(16) │ HMAC_D(32) │ CT_DECOY(M) [ghost layer]  │
 │  |META|(6) │ DECOY_LEN(4) │ META_IV(16) │ META_LEN(4) │ META_CT  │
 └────────────────────────────────────────────────────────────────────┘
```

</div>

| Layer | Algorithm | Spec |
|-------|-----------|------|
| **Key Derivation** | PBKDF2-HMAC-SHA256 | 600,000 iterations, 32-byte output |
| **2FA Blending** | XOR with SHA256(keyfile) | Requires physical key file |
| **Compression** | zlib DEFLATE | Level 6, pre-encryption |
| **Encryption** | AES-256-CBC | Random 128-bit IV per file |
| **Integrity** | HMAC-SHA256 | Encrypt-then-MAC pattern |
| **Deniability** | Dual-payload container | Decoy layer indistinguishable |
| **Shredding** | DoD 5220.22-M | Random → 0x00 → 0xFF → delete |

## ⚙️ Installation & Setup

<details>
<summary><b>Step 1 — Prerequisites</b></summary>
<br/>

| Tool | Required Version | Check Command |
|------|-----------------|---------------|
| Node.js | `v18.0+` | `node --version` |
| Python | `3.10+` | `python --version` |
| MySQL | `8.0+` | `mysql --version` |
| Git | any | `git --version` |
| Docker | optional | `docker --version` |

</details>

<details>
<summary><b>Step 2 — Clone</b></summary>

```bash
git clone https://github.com/shakibdev2-source
/SecureLocker-Ultra.git
cd SecureLocker-Ultra
```

</details>

<details>
<summary><b>Step 3 — Backend (Node.js + Express + MySQL)</b></summary>

```bash
cd backend
npm install

# Copy and configure environment
cp .env.example .env
nano .env   # fill in DB credentials, JWT secrets

# Run database migrations
npx prisma migrate dev

# Start dev server
npm run dev
# API live at http://localhost:5000
```

</details>

<details>
<summary><b>Step 4 — Frontend (Next.js)</b></summary>

```bash
cd frontend
npm install

cp .env.local.example .env.local
nano .env.local  # set NEXT_PUBLIC_API_URL

npm run dev
# App live at http://localhost:3000
```

</details>

<details>
<summary><b>Step 5 — Desktop Client (Python)</b></summary>

```bash
cd desktop

# Windows — double-click SETUP_AND_RUN.bat, OR:
pip install cryptography Pillow tkinterdnd2
python locker.py

# Linux / macOS
pip3 install cryptography Pillow
python3 locker.py
```

</details>

<details>
<summary><b>Step 6 — Docker (One command setup)</b></summary>

```bash
# Start all services
docker-compose up -d

# Services:
#   Frontend  →  http://localhost:3000
#   Backend   →  http://localhost:5000
#   MySQL     →  localhost:3306
#   Adminer   →  http://localhost:8080

# Stop everything
docker-compose down
```

</details>

### 🎭 Decoy Mode

```
Real Password  ─→  Real File
Wrong Password ─→  Fake File
```

Full **plausible deniability** under duress. One `.locked` container holds two entirely separate AES-256 encrypted payloads. From the outside — mathematically indistinguishable.

**Use case:** border crossing, coercion, warrant compliance

</td>
<td align="center" width="33%" valign="top">

### 🖼️ Steganography

```
Secret File
    ↓ AES-256 encrypt
    ↓ LSB embed in pixels
Normal PNG output
```

Hidden file is encrypted **before** embedding. Output PNG is visually **identical** to source. No metadata changes. No file size anomaly clues.

**Use case:** covert file transfer, hidden messages

</td>
<td align="center" width="33%" valign="top">

### 🔑 Two-Factor KeyFile

```
Password  ─┐
           ├─ XOR ─→ Final 256-bit Key
.key file ─┘
```

Both the password **and** the physical `.key` file are required. Stolen password alone = **zero access**. Lost key file = **permanent lockout** (no recovery).

**Use case:** high-value files, multi-party custody

</td>
</tr>

## 🛡️ Security Architecture

<div align="center">

```
 Password + Salt (32 bytes random)
          │
          ▼
   PBKDF2-SHA256
   600,000 iterations
          │
          ▼
   256-bit Base Key ──── XOR ────  SHA256(KeyFile)   ← optional 2FA
          │
          ▼
   zlib.compress(plaintext)
          │
          ▼
   AES-256-CBC  ←──  random IV (128-bit)
          │
          ▼
     Ciphertext
          │
          ▼
   HMAC-SHA256(Ciphertext)  →  integrity tag

   ┌──────────────────────────────────────────────────┐
   │ MAGIC(7) │ SALT_R(32) │ IV_R(16) │ HMAC_R(32)   │
   │ CT_REAL                                          │
   │ SALT_D(32) │ IV_D(16) │ HMAC_D(32) │ CT_DECOY   │
   │ |META|(6) │ MetaIV(16) │ MetaCT (AES encrypted)  │
   └──────────────────────────────────────────────────┘
                    .locked output file
```

</div>

| Layer | Algorithm | Purpose |
|-------|-----------|---------|
| **KDF** | PBKDF2-SHA256 (600K iterations) | Slow brute-force, derive key |
| **2FA** | SHA256(keyfile) XOR base_key | Second factor — both required |
| **Confidentiality** | AES-256-CBC | Data encryption |
| **Integrity** | HMAC-SHA256 | Detect tampering |
| **Deniability** | Decoy Mode | Duress / coercion protection |

</td>
<td align="center" width="33%">

```

           ├─→ XOR → Final Key
KeyFile ───┘
```

## 🛡️ Security Architecture

<div align="center">

```
Password + Salt
      │
      ▼
 PBKDF2-SHA256
 (600,000 iter)
      │
      ▼
  256-bit Key  ──── XOR ────  SHA256(KeyFile)   [optional 2FA]
      │
      ▼
 zlib.compress(plaintext)
      │
      ▼
 AES-256-CBC  ──  random IV (128-bit)
      │
      ▼
  Ciphertext
      │
      ▼
 HMAC-SHA256(Ciphertext)  ──  integrity tag
      │
      ▼
  ┌─────────────────────────────────────────────┐
  │ MAGIC │ SALT │ IV │ HMAC │ CT_REAL           │
  │ SALT_D│ IV_D │ HMAC_D │ CT_DECOY [ghost]    │
  │ |META| │ MetaIV │ MetaCT (encrypted)         │
  └─────────────────────────────────────────────┘
              .locked file
```

</div>

| Layer | Algorithm | Purpose |
|-------|-----------|---------|
| KDF | PBKDF2-SHA256 (600K iter) | Slow brute-force, derive key |
| 2FA | SHA256(keyfile) XOR key | Second factor requirement |
| Confidentiality | AES-256-CBC | Data encryption |
| Integrity | HMAC-SHA256 | Tamper detection |
| Plausible Deniability | Decoy Mode | Duress protection |

**SECURE_NET** is a next-generation, high-fidelity cyber-warfare intelligence dashboard. Specifically engineered for elite clandestine operations, it provides an unparalleled modular interface for managing operative dossiers, analyzing global threat vectors, and coordinating real-time classified data streams.

* **Backend-Connected RESTful APIs:** Complete integration with normalized database entities via dedicated controllers (`targetController.js`, `authController.js`) and robust routing (`targetRoutes.js`, `authRoutes.js`).

### System Initialization

1. **Initialize Primary Unit:**
```bash
git clone https://github.com/shakibdev2-source/agent-profile-management-system.git
cd agent-profile-management-system/agent-profile-dashboard

```


2. **Inject Dependencies:**
```bash
npm install

```


3. **Configure Tactical Environment:**
Create a `.env` file in the root directory and configure your secure telemetry connection:
```env
PORT=5000
DB_HOST=localhost
DB_USER=root
DB_PASSWORD=your_password
DB_NAME=phantom_unit_db
NEXT_PUBLIC_API_URL=http://localhost:5000/api/phantom

```


4. **Initialize Secure Operations:**
```bash
npm run dev

```


5. **Access Terminal:**
Navigate to `http://localhost:3000` on your secure network.

## 📡 API Endpoints Reference

The system core interacts via the following tactical REST API endpoints.

### Authentication (`/routes/authRoutes.js`)

* `POST /api/auth/login` — Authenticates user credentials and assigns clearance roles.

### Intelligence Dossier (`/routes/targetRoutes.js`)

* `GET /api/phantom/data` — Fetches unified JSON records across all operational tables.
* `POST /api/phantom/update` — Commits administrative modifications directly to the database.
