## 🛡️ Security Architecture

<div align="center">

```
 Password + Salt (32 bytes random)
          │
          ▼
   PBKDF2-SHA256
   600,000 iterations
          │
          ▼
   256-bit Base Key ──── XOR ────  SHA256(KeyFile)   ← optional 2FA
          │
          ▼
   zlib.compress(plaintext)
          │
          ▼
   AES-256-CBC  ←──  random IV (128-bit)
          │
          ▼
     Ciphertext
          │
          ▼
   HMAC-SHA256(Ciphertext)  →  integrity tag

   ┌──────────────────────────────────────────────────┐
   │ MAGIC(7) │ SALT_R(32) │ IV_R(16) │ HMAC_R(32)   │
   │ CT_REAL                                          │
   │ SALT_D(32) │ IV_D(16) │ HMAC_D(32) │ CT_DECOY   │
   │ |META|(6) │ MetaIV(16) │ MetaCT (AES encrypted)  │
   └──────────────────────────────────────────────────┘
                    .locked output file
```

</div>

| Layer | Algorithm | Purpose |
|-------|-----------|---------|
| **KDF** | PBKDF2-SHA256 (600K iterations) | Slow brute-force, derive key |
| **2FA** | SHA256(keyfile) XOR base_key | Second factor — both required |
| **Confidentiality** | AES-256-CBC | Data encryption |
| **Integrity** | HMAC-SHA256 | Detect tampering |
| **Deniability** | Decoy Mode | Duress / coercion protection |

## ⚙️ Installation & Setup

<details>
<summary><b>📋 Prerequisites</b></summary>
<br/>

| Tool | Minimum Version | Check |
|------|----------------|-------|
| Node.js | v18+ | `node --version` |
| Python | 3.10+ | `python --version` |
| MySQL | 8.0+ | `mysql --version` |
| Git | any | `git --version` |

</details>

<details>
<summary><b>Step 1 — Clone the repository</b></summary>

```bash
git clone https://github.com/shakibdev2-source/SecureLocker-Ultra.git
cd SecureLocker-Ultra
```

</details>

<details>
<summary><b>Step 2 — Backend Setup (Node.js + Express)</b></summary>

```bash
cd backend
npm install
cp .env.example .env
# Edit .env with your MySQL credentials
npm run migrate
npm run dev
# API running at http://localhost:5000
```

</details>

<details>
<summary><b>Step 3 — Frontend Setup (Next.js)</b></summary>

```bash
cd frontend
npm install
cp .env.local.example .env.local
# Edit .env.local with your API URL
npm run dev
# App running at http://localhost:3000
```

</details>

<details>
<summary><b>Step 4 — Desktop Client (Python)</b></summary>

```bash
cd desktop

# Windows — double-click:
SETUP_AND_RUN.bat

# Or manually:
pip install cryptography Pillow tkinterdnd2
python locker.py
```

</details>

<details>
<summary><b>Step 5 — Docker (All-in-one)</b></summary>

```bash
docker-compose up -d
# Frontend  → http://localhost:3000
# Backend   → http://localhost:5000
# MySQL     → localhost:3306
```

</details>

## 🎭 Special Modes

<table>
<tr>
<td align="center" width="33%">

### 🎭 Decoy Mode
```
Real Password  →  Real File
Wrong Password →  Fake File
```
Plausible deniability under duress. Two separate encrypted payloads inside one `.locked` container — indistinguishable from outside.

</td>
<td align="center" width="33%">

### 🖼️ Steganography
```
Secret File + PNG
      ↓ AES-256
Hidden in pixels
      ↓ LSB embed
 Normal PNG out
```
Output image looks **100% identical** to the naked eye. No metadata, no header changes.

</td>
<td align="center" width="33%">

### 🔑 Two-Factor (2FA)
```
Password  ─┐
           ├─→ XOR → Final Key
KeyFile ───┘
```
Without **both** the password **and** the `.key` file, decryption is **mathematically impossible**.

</td>
</tr>
</table>

## 🛡️ Security Architecture

<div align="center">

```
Password + Salt
      │
      ▼
 PBKDF2-SHA256
 (600,000 iter)
      │
      ▼
  256-bit Key  ──── XOR ────  SHA256(KeyFile)   [optional 2FA]
      │
      ▼
 zlib.compress(plaintext)
      │
      ▼
 AES-256-CBC  ──  random IV (128-bit)
      │
      ▼
  Ciphertext
      │
      ▼
 HMAC-SHA256(Ciphertext)  ──  integrity tag
      │
      ▼
  ┌─────────────────────────────────────────────┐
  │ MAGIC │ SALT │ IV │ HMAC │ CT_REAL           │
  │ SALT_D│ IV_D │ HMAC_D │ CT_DECOY [ghost]    │
  │ |META| │ MetaIV │ MetaCT (encrypted)         │
  └─────────────────────────────────────────────┘
              .locked file
```

</div>

| Layer | Algorithm | Purpose |
|-------|-----------|---------|
| KDF | PBKDF2-SHA256 (600K iter) | Slow brute-force, derive key |
| 2FA | SHA256(keyfile) XOR key | Second factor requirement |
| Confidentiality | AES-256-CBC | Data encryption |
| Integrity | HMAC-SHA256 | Tamper detection |
| Plausible Deniability | Decoy Mode | Duress protection |

      ↓  AES-256
 Hidden in pixels

Image looks 100% identical to the naked eye.

Password  ──┐
            ├─→ XOR → Final Key

## 🌐 Project Overview

**SECURE_NET** is a next-generation, high-fidelity cyber-warfare intelligence dashboard. Specifically engineered for elite clandestine operations, it provides an unparalleled modular interface for managing operative dossiers, analyzing global threat vectors, and coordinating real-time classified data streams.

This system is designed not just for data management, but to provide a complete, immersive **tactical overview**. It delivers advanced **Role-Based Access Control (RBAC)**, multi-tier clearance handling, and dynamic CRUD operations mapped directly to a sophisticated, normalized relational database.

---

## 🚀 Key Features

* **Modular Component Architecture:** Decoupled UI blocks ensure clean, scalable, and maintainable code.
* **Role-Based Access Control (RBAC):**
* **Viewer:** High-clearance, read-only monitoring and dossier review.
* **Admin:** Interactive modal forms for modifying records and committing changes directly to the intelligence core.


* **Tactical Cyber-UI/UX:** A dark-mode, cyberpunk aesthetic with glassmorphism containers, CRT grid lines, glowing tactical pulses, and seamless state-managed UI switching between operative roles.
* **Backend-Connected RESTful APIs:** Complete integration with normalized database entities via dedicated controllers (`targetController.js`, `authController.js`) and robust routing (`targetRoutes.js`, `authRoutes.js`).

---

## 🗄️ System Architecture & Schema

### Intelligence Core (Database Structure)

The backend relational database maps core intelligence entities across four normalized SQL tables to ensure data integrity and operational secrecy:

1. **`target_identity`**: Primary biometric markers, physical attributes, personal history, alias details, and profile images.
2. **`operative_details`**: Tracking active field status, military/covert ranks, unit divisions, clearance levels, and deployment locations.
3. **`psychological_profile`**: Behavioral assessments, cognitive stability, stress tolerance thresholds, and risk analysis.
4. **`users`**: System authentication credentials, clearance grades, and role privileges.
